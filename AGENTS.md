# Architecture Decisions
- Cash Position uses scoped page tokens and existing read-only account totals for its charts/table; unreported available/pending balances and historical account snapshots are never fabricated to match a design reference.
- FloatingToolbar owns the single global Welile Assistant launcher and open-welile-assistant event; AgentAssistant and deep-linked WelileAIChatDrawer share AssistantChatSurface built on AI Elements. Personal history stays server-owned, never enters public AI history, and account transitions abort and clear local chat.
- Nexa public account, wallet, pledge, starter-intent and financial-access guidance shares pure helpers under `supabase/functions/_shared/` with browser re-exports; privacy guidance precedes financial topics and model/learning reads, phone input never authenticates, and public fallbacks never mask terminal AI denials, refusals or service configuration errors.
- Nexa inquiry signup uses shared intent helpers and the existing consent-based signup page; chat never creates accounts, checks public account existence, transports passwords or grants roles, because a supplied phone is not proof of ownership.
- Nexa sales helpers are projections only; house completeness sorts already authorized loaded rows without replacing verification or funding rules. Private escalation writes and teaching use caller-checked RPCs; role-scoped knowledge never crosses roles and WhatsApp numbers never authenticate accounts.
- Nexa schema proposals remain under docs/pending-migrations until applied through the approved migration workflow; Meta webhook requires a signed body and configured sender, with no duplicate fallback after uncertain delivery.
- Nexa public catalog and internal-query firewall are shared between browser and server; public chat refuses internal questions before escalation or model calls, even for staff sessions, to prevent public-channel disclosure.
- Tenant campaign progress reads the caller-checked `rent_access_limit_server` RPC; failed reads show unavailable rather than estimating from partial payment rows or changing financial rules.
- Partner payout presentation reuses existing paid/outstanding reports and drill-downs; tiles keep original totals and due-by cutoff, never an invented next due date.
- Nearing Payout checks fresh unused CFO cycle permissions before its friendly duplicate warning, attaches the permission to the existing payout request and retains requester/amount/queue checks; only the server authorizes and consumes it.
- Standing order amount revisions use only `standing_order_set_amount` for locked configuration plus atomic audit, never the payer or lifecycle audit helper; authorized users may preview, but saves remain loopback-development-only until separately approved activation.
- CFO loading separates authoritative summaries from optional detail reads; shared wallet responses retain distinct balance/float fields and reconciliation still waits for the full verification scan, so faster presentation cannot change financial definitions.
- Financial Ops presentation is opt-in through FinOpsScope and semantic scoped CSS; shared UI surface attributes carry React context through portals without changing other workspaces or any financial behavior.
- Recruitment profile links reuse AgentProfile360Sheet and its role-gated read, so returning keeps the recruiter's tab without duplicating data or access.
- Automated Calls UI lives in crm/autocall behind useCanUseAutocall and uses the voice-autocall hook exclusively for calling state and playback; overview demos use a separate server-owned destination/config and one-shot action, never changing roles, campaigns or the original staff-test action.
- Payables forecast hooks do not automatically replay deterministic database timeout/permission failures; server reporting remains the sole authority for amounts.
- The new agent dashboard rent-request card opens the existing lazily loaded AgentRentRequestDialog; promotional presentation never duplicates submission or financial logic.
- Service Centre intake actions use the live typed RPC contract and require its returned request/status before showing success; persistent row errors prevent silent failures.
- Landlord principal comparison is a read-only enabled-role RPC: cumulative non-cancelled float allocations versus non-reversed principal; collected fee totals exclude principal and never add gross fees to their allocation breakdown.
- Welile Schools gate registration stores only in `welile_schools` / `welile_school_profiles` (agents see their own profiles, `welile_schools_ops_ok()` roles see all, no deletes); offline profiles queue locally and retry idempotently via `client_ref`.
- Welile Homes float requests move only through `src/lib/welileHomesFloat.ts` (`wh_request_float`/`wh_float_advance`) and CFO money only via `wh_cfo_disburse_float` (Merchant `agent_float_deposit` legs, no fallback); "funded" is set only by disbursement and Merchant desks exclude Welile Homes requests.
- Welile Schools chat and classic registration share one page-owned draft and save handler, with Uganda hierarchy supplied by the shared location picker, so switching modes cannot fork registration data.
- Welile Homes plan stage and Delete lock come only from `src/lib/welileHomesPlanStatus.ts`, using recorded facts (subscription/funding status, float link, collected dues), never reason text; Funded needs funding_status = 'funded', a rejected float request is not a declined application, unknown collections lock Delete, and `delete_welile_home_subscription` refuses the same server-side.

- Requisition approval errors are normalized client-side; the server authorizes.
- CRM Broadcast is the visible destination for the existing in-app communications publisher; its earlier section id remains an alias so saved links keep working.
- Four-part repayment validation reconciles Returns + Agent Commission + Platform Fee to Access Fee + Registration Fee (the approved Platform Fee pool).
- CFO 7-day reports use Kampala days via `src/lib/kampalaDays.ts`.
- Shopping Advance counts/dossiers use one received-transfer ledger helper behind role-gated RPCs; no financial writes.
- Support capacity and its debit use operational float only, never withdrawable Returns.
- `sofp_ledger_legs` reads advance top-up legs as A10 and emits no X4 for bucket_reclass pairs (CFO approved 2026-10-01).
- `v_agent_daily_eligibility` falls back to LEAST(daily_repayment, outstanding) only when no pinned bill exists today/yesterday.
- CRM call drawer loads one cached role-gated `crm_callee_dossier`; partner visibility is decided server-side. Wallet totals read `wallet_balances_projection` (one row), and `user_wallet_strict_for` only when that row is missing — never `v_user_wallet_strict` (recomputes every wallet).
- CFO TIN/NSSF list derives per paid payroll run (`cfo_statutory_consent_list`).
- CFO correction/evidence tooling (Correction Center, `cfo_s12_save_evidence`, Stage 14 `fin_s14_*`, `cfo_s14b1r/b1w_execute`) is append-only, role-gated and scoped, so review never moves money or touches other users.
- Fingerprinted CFO packages (`cfo_bucket_a_post`, `cfo_corr_5300000_post`) post only via their own function: approver allowlist, own fresh preflight (<30 min), frozen lines, atomic.
- Business-line cost attribution lives in append-only `cfo_reporting_cost_tags`, never correcting journals.
- Rent Plan landlord/LC1 verification (bonus release) fires only on the first Landlord Ops review transition.
- Phone wallet collection runs only for `phone_collection_enabled` plans; late charge only when `smartphone_surcharge_enabled`.
- Agent lending is excluded from company Receivables (agents' own money); Payables mirrors Receivables read-only.
- Merchandise plans count as owed only if `merchandise_plan_recovery_eligible` passes (no phantom receivables).
- Landlord awareness calls store consent + `aware_payout_otp` (not merchant codes) only via append-only `record_awareness_call`; pre-2026-10-08 answers kept via a legacy CHECK branch; never affects approvals.
- Float send-backs auto-complete only when funded/unpaid/open/no payout, via single helper `_complete_allocation_return`; sender can't self-approve; amount edits go through `agent_edit_sent_back_rent_plan`.
- Tenant SMS campaigns send only via `tenant-campaign-sender`, unique `dedupe_key` per tenant, wave stops above 20% failures.
- Landlord payout numbers lock at COO/CFO stage (`lock_landlord_number_at_cfo_stage`); payouts use the approved number.
- Overdue-vetting dialog mounts once in App.tsx from server `get_my_overdue_vetting`; Service Centre shows a banner instead.
- Sign-up client pre-checks run in parallel, capped at 1.5s, and fail open; only server checks enforce.
- Subdirectories have their own `AGENTS.md` to read before changing files there: `src/lib/` (incl. `assetRegister/`), `src/components/requisitions/`, `src/components/executive/agent-ops/` (First 7 Days files maintained upstream — do not restyle) and `supabase/` (one named server function is the only definition; the client never recomputes it).

- Supporter agreement review text is transcribed from the approved partner contract asset; download and print open that original PDF so exports cannot substitute obsolete terms.
- Supplementary budgets live only in `budget_supplements` / `budget_supplement_*` RPCs; the original approved line is never edited, revised = original + CFO-approved supplements via `budget_revised_position`, and supplements never touch disbursements, ledger or wallets.
- Staff requisitions: COO → CEO → CFO, except the active Product R&D budget head (CEO → CFO via `staff_requisition_ceo_direct`, enforced in the database).
- Approved `pending_wallet_operations` never return to waiting (`trg_guard_pwo_approved_not_reopened`); stage approvals filter on expected current status.
- `submit_proxy_split_withdrawal` must always write a real uuid into `withdrawal_requests.client_request_id` (`gen_random_uuid()`, never `md5(...::text)`); a text expression makes every proxy split withdrawal fail with a uuid/text type error.
- Background device checks send an explicit fresh token for the current account, coalesce overlapping calls and retry authentication once; failures preserve any known verification requirement without becoming page crashes.
- Landlord Ops Calling Center reuses the shared `cc_*` engine over `v_landlord_registry_all` (deduped by `user_id` then phone, unclear matches flagged without guessed merges), with saved queues, advisory caller splits, and the seven read-only `landlord_cc_*` reports; Tenant Ops calling and reports untouched.
- Welile Medicine mirrors Welile Schools: records live only in `welile_medical_*` gated by `welile_schools_agent_ok()` / `welile_schools_ops_ok()` (no deletes); every gate log, receipt and profile is written locally first and retried idempotently by `client_ref`. Receipts never move wallet or ledger money.
- My Space Calling & Pipeline Feedback reports (`/me/reports` for Jane, Winnie, Hanisha; `/me/staff-reports` for HR/Mark Bwayo) read only `staff_calling_detailed_report(p_from, p_to)` across Wednesday–Tuesday Kampala weeks and calendar months, unioning Tenant & Landlord Calling Centers and Rent Plan pipeline calls/reviews; financial state untouched.
- CFO Asset Register rules (RPC-only access, server-issued codes/tags, append-only events, private evidence, QR grants nothing) live in `src/lib/assetRegister/AGENTS.md`; read it before touching any asset register code, page or migration.
- Agent Verification screens use only the agent-vetting hooks and `src/lib/agentVetting.ts`; blocked creates go through `promptIfNotVetted` to one app-level dialog and the client never hides Add Tenant / Rent Plan buttons, because only the server decides verification.
- Lunch allowance reclasses are append-only pairs logged once in `cfo_lunch_reclass_log`; Money Out counts the reclass, not the original, to avoid double counting.
- CFO Money Out/Money In read only their `get_cfo_paid_by_category_*` / `get_cfo_received_by_category_*` RPCs; category maps live only in `_cfo_paid_category_for` / `_cfo_received_category_for`; the client never recomputes or re-labels, so each report has one server definition.
- New-plan 360-day pricing lives only in `src/lib/contractEngine360.ts` (mirrored by `compute_rent_repayment_v360` once applied); plans are versioned by `pricing_version` so legacy plans never reprice.
