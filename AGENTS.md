# Architecture Decisions
<!-- LOVABLE:BEGIN -->
- Receivables Analysis uses existing read-only reporting RPCs; aggregate totals outrank sampled items, behavioural runoff excludes new business, and unsupported location forecasts stay unavailable to prevent invented figures.
<!-- LOVABLE:END -->

- Requisition approval errors are normalized only in the client; server authorization remains the sole permission authority.
- Four-part repayment validation reconciles Returns + Agent Commission + Platform Fee to Access Fee + Registration Fee, because those two stored fee components form the approved Platform Fee pool.
- CFO 7-day reporting labels and day buckets use Kampala (EAT, UTC+3) calendar days through `src/lib/kampalaDays.ts`, matching the reporting RPCs; browser-local dates shifted cards by a day.
- Agent Ops opens on 14 business-area entry panels, while all legacy views remain reachable through the collapsible desktop sections menu or mobile sections menu, so reorganizing the landing view never removes management data.
- Agent Ops Shopping Advance qualification (distinct outbound peer-transfer senders across legacy and ledger records) and each user's full read-only dossier come from role-gated server functions, so legacy transfers count, limits aren't mistaken for issued credit, and details stay consistent.
- Supporter/partner support capacity and the funding debit use operational float only (`funder_support_capacity` = `funder_float_available`); withdrawable money is never used to fund support, so Returns stay withdrawable and support never drains them.
- Balance Sheet (`sofp_ledger_legs`) reads advance top-up company legs as Agent Advance Receivable (A10) and emits no synthetic X4 lines for bucket_reclass_in/out pairs, because top-ups move no bank cash and reclass pairs already balance (CFO approved 2026-10-01).
- `v_agent_daily_eligibility` falls back to LEAST(daily_repayment, outstanding) for counted daily/lapsed-weekly plans only when the agent has no pinned bill today/yesterday, because counted plans with no bill row showed a UGX 0 target.
- The CRM call drawer paints directory identity immediately, then loads the full dossier through one cached server function, `crm_callee_dossier`, which decides partner visibility (partner_ops / super_admin / hr only); this prevents duplicate reads without moving role enforcement into the browser.
- CFO bulk rent payments use a local selection-only review screen and revalidate every selected request before the existing payment function is called, so opening bulk review can never move money or change workflow state.
- The CFO staff TIN/NSSF list is derived per paid payroll run (`cfo_statutory_consent_list`) and its push fires from the `paid` payroll event, because the list must reappear after each survey-and-payment cycle without polling.
- The CFO Correction Center reads only the evidence-review tables (`fin_correction_review_items`, `fin_correction_approval_batches`) through role-gated server functions; "Approve" records an append-only decision whose execution status is locked to not executed, so no correction can move money until a separate, approved execution workflow exists.
- CFO Correction Center evidence reviews are saved only through `cfo_save_evidence_review`, which writes review fields plus an append-only `fin_correction_review_audit` row; matching checks only flag, and `is_test` rows are excluded from every total and approval, because review must never touch financial records.
- `cfo_s12_save_evidence` accepts an evidence file only inside the owning collection's folder of the private `collection-evidence` bucket and only if the file exists, so evidence can't be cross-attached or point outside storage.
- Stage 14 evidence recovery writes only `fin_s14_cases`/`fin_s14_evidence`/`fin_s14_audit` through `cfo_s14_add_evidence`/`cfo_s14_decide`, which assert Stage 11/12 control totals and zero financial-table writes before and after; evidence and history are append-only and Stage 12 history is never rewritten, so case resolution can never move money.
- Rent Plan writes verify a linked landlord or LC1 (and so release registration bonuses) only on the first Landlord Ops review transition (review date NULL → set), via `verify_landlord_on_landlord_review` / `verify_lc1_on_landlord_review`, because generic status writes (repayments, reversals, corrections) were releasing bonuses.
- Batch 1 restoration (`cfo_s14b1r_execute`) adds restored amounts to pinned current Rent Plan values (never overwrites, so later genuine payments survive); the three wallet balance rules count correction credits only for its 13 wallet lines matched by key, agent and amount to frozen `fin_s14b1r_lines`, so correction credits can never otherwise inflate balances.
- The Batch 1 three-agent stored-balance refresh runs only via `cfo_s14b1w_execute`, gated by a single-use CFO approval bound to a sha256 manifest fingerprint and the live rule definitions, so it can never touch the ledger, other buckets or other users.
- Phone wallet collection runs only for plans with `phone_collection_enabled` (daily `recover_smartphone_from_wallets`), apart from the bike job, so phones start one plan at a time; it may draw advance-locked funds (withdrawals stay locked); the phone late charge runs only when `smartphone_surcharge_enabled` is on.
