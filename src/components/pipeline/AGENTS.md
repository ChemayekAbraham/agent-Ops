# Pipeline decisions
- "Your awareness calls" renders an empty state when the report says not authorized, and does not offer Retry. Who is fetched, and how often, is decided in `useMyAwarenessCalls`.
- Landlord awareness calls ask for consent (`landlord_consent`: consents / unsure / refuses) and for knowledge of the payment code (`aware_payout_otp`) instead of the merchant-code question, because a landlord is paid through the payout code and does not pay by merchant code; tenant and agent calls keep `aware_merchant_codes`. Landlord calls recorded before 2026-10-08 09:00 UTC keep their old merchant-code answer through an explicit legacy branch of the answers CHECK (the screens read it as "Old question", with "Not asked" for the new questions), and the merchant-code counts only cover tenant and agent calls. The answers are stored only through `record_awareness_call`, are append-only, and never block or change an approval or rejection.
- The time a Rent Plan application has spent at its current desk, at the immediately preceding visit and in total comes only from `rent_request_timing(p_request_ids)` (batch of at most 200, ONE server `as_of` per answer) and `rent_request_timing_history(p_request_id)` (the visit-by-visit journey, on demand), migration `20261019170000` (SECURITY DEFINER, STABLE, read-only, `search_path = public`; authenticated only; the helpers `_rt_*` are owner-only; the logic is `_rt_compute`, pure and tested at a fixed server time in `supabase/tests/rent_request_timing.sql`). Visibility is exactly the rent_requests SELECT policies (a request the caller cannot see is left out of the answer). Desks in order: service_center, agent_ops, tenant_ops, landlord_ops, partner_ops, coo, cfo; status -> desk: service_center_review, pending, agent_ops_approved / agent_verified, tenant_ops_approved, landlord_ops_approved, partner_ops_approved, coo_approved (do not invent financial_ops_approved). The current visit is the latest ACTUAL entry into the desk (the previous desk's approval stamp, the Service Centre verification, a resubmission, a force approval, or a stale stamp of a later desk as a labelled lower bound after a return), never `updated_at`; the previous visit is the immediately preceding actual visit including correction waiting; a skipped desk has no visit; the total starts at the request's own `created_at` (a renewal has a fresh clock) and is frozen at the processing endpoint (`funded_at`, `rejected_at`, the withdrawal event), while the landlord payment wait is reported separately under `payout` and is approximate; elapsed seconds, no working-day rule, no overdue threshold; quality is confirmed / estimated / unavailable with a missing reason. History sources: `rent_requests` stamps, `system_events` and `audit_logs` (de-duplicated per transition within 2 seconds), `agent_landlord_float_allocations` (landlord payment time). `service_center_request_events.request_id` is a `service_center_requests` id, not a rent request id, and `agent_ops_pipeline_stage_events` is agent-profile history: neither is used. Do not parse notes into handovers, do not use `*_reviewed_at` alone as proof of an approval beyond the rules above, and do not recompute any of it in the client (`src/lib/rentTiming.ts` only types and formats). A minimal append-only recorder (`docs/RENT_TIMING_RECORDER_PROPOSAL.md`) is proposed and NOT applied; UI wiring is in `docs/RENT_TIMING_UI_CONTRACT.md`.
- Who the registering agent, the main (parent) agent and the assigned agent of a Rent Plan application are, and which phone belongs to which person, comes only from `rent_request_agent_chain(p_request_ids)` (migration `20261019180000`; SECURITY DEFINER, STABLE, read-only, `search_path = public`; authenticated only, desk roles only, at most 200 ids per call). The parent is decided there and nowhere else: a main agent exists only for an `agent_subagents` link with `status = 'verified'`; pending, expired and rejected links show no main agent. Never join `agent_subagents` in a card query, and never show one agent's name next to another agent's phone.
- Desk time on the rent cards is wired once per desk: `useRentRequestTiming(ids)` on the ids already loaded (first 200 of the visible page), `timingRow()` per card, and `useRentRequestTimingHistory` only when a journey is opened. No browser time computation, no `Date.now()` and no `updated_at` for these figures.
