# Asset Register rules

- CFO Asset Register (Stage 1, `supabase/migrations/20261026200000_asset_register_stage1.sql` applied 2026-10-26; storage policies from `20261026200100_asset_register_stage1_storage_policies.sql` created by the project owner in the dashboard the same day under the names `asset_evidence_read 1iodt3o_0` / `asset_evidence_insert 1iodt3o_0` (only the owner of `storage.objects` can create them, not the CLI's postgres login); rollbacks find them by what they reach, not by name) reads and writes only through `asset_register_*` SECURITY DEFINER RPCs (read and write: cfo/super_admin plus `staff_mfa_ok()`; ceo/coo read access pending CFO review); scope is Welile-owned, Welile-used tangible assets (bikes, resale stock, smartphones and NFC cards excluded pending review); asset codes are server-generated, serials are unique per category, `asset_events` is append-only, imports are all-or-nothing inserts that never overwrite, and evidence stays in the private `asset-evidence` bucket behind 5-minute signed URLs. Purchase cost is register information only and never touches the ledger, wallets or payments. Asset QR codes (`src/lib/assetRegister/qr.ts`) encode only `https://welileapp.com/cfo/assets/<uuid>`; that route is `SignInReturnGate` (signed-out → `/auth?redirect=`) + `RoleGuard` cfo/super_admin, and the page is read-only and still relies on `asset_register_get` and storage RLS, so a QR grants nothing. Labels print only the company name, QR, asset code, category, site and location and a "Property of Welile" footer (location approved by the user 2026-10-26); serial, cost, supplier, custodian and invoice never print. Asset tags (`20261027150000_asset_register_asset_tags.sql`, not yet applied; CFO 2026-10-27): `WEL-<ICT|FUR|OFE|VEH|MAC|OTH>-<site tag code>-<WEL-AST number, ≥3 digits>` (e.g. `WEL-ICT-HQ-001`), issued only by the server (`_asset_register_make_tag`) at registration/import from the required site (`asset_sites`: Entebbe Head Office HQ, Kololo KOL), unique, and fixed forever by the identity trigger (site/category changes never re-issue it); `WEL-AST-NNNNNN` stays the permanent code and the uuid stays the QR identity. Labels and screens show the tag prominently with the permanent code smaller (`assetCodes()`); the browser never builds a tag. Pre-tag assets stay untagged until the separately approved `docs/pending-migrations/asset_register_tag_backfill_wel_ast_000001.sql`.
